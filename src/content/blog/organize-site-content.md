页面一多，个人站就容易变成一堆互不相关的文件：有的写在 Markdown 里，有的写死在模板里，改一个标题要找三个地方。先分清一段内容是什么，再决定它出现在哪一页。

## 文章和项目分开

这个站点把内容分成博客和项目。博客按时间读，项目是可以单独介绍的练习或示例。两者都放在 `src/content` 下，各用各的目录，frontmatter 不混用。

文章至少要有标题、摘要和日期。标签与草稿有默认值，不写也会通过校验：

```yaml
title: 用 Astro 搭建静态个人站
description: 从目录、内容集合到一次本地构建。
date: 2026-09-18
tags:
  - Astro
draft: false
```

项目关心简介、技术栈、是否出现在首页，以及排序：

```yaml
title: 个人博客示例
description: 用来练习列表和静态生成的示例，不是已上线的产品。
tech:
  - Astro
  - Markdown
featured: true
order: 1
```

链接和仓库地址是可选项。要写，就必须是合法 URL。没有可公开的地址时就不要填，尤其不要填一个看起来像真实产品的链接。示例就在简介里写明它是练习。

## 首页只放一部分

首页不必铺满全部条目。文章按日期从新到旧取几篇；项目只取 `featured` 为 true 的，再按 `order` 从小到大排。仍在草稿阶段的练习可以留在项目总表，不占首页。

文章草稿把 `draft` 设为 true。列表和文章路由都会滤掉它，文件继续留在仓库里。想发表时改成 false，不用把正文搬来搬去。

`order` 用整数，中间留出空隙，例如 10、20、30。以后想插到中间，不必把后面的编号全部加一。数字只表示相对顺序，不表示这是第几个作品。

## 摘要不要复述正文

摘要给列表和卡片用，正文给点进去的人看。摘要写成一两句人话，说明这篇在讲什么，不要把第一段原样再贴一次。项目描述同样短：它练习什么，以及它不是什么。个人站里最容易让人误会的，是把练习写成已经对外提供服务的产品。写明「示例」「练习」或「模板草稿」，读者就知道该如何理解。

不确定的个人信息不要写成具体事实。城市、方向、邮箱，没有核对过就用占位，并标上 TODO。名字、导航和社交链接集中在站点配置里，关于页和页脚不要各写一套。关于页可以说明这个站是干什么的，但不要编一段没有来源的经历。

## 一次只加一块

新增文章时，复制上一篇的 frontmatter，改标题、摘要和日期。正文里放小标题，方便以后扫读。新增项目时，先决定它要不要上首页，再填 `order`。改完运行一次构建。字段类型不对时命令会失败，比靠肉眼对每一张卡片可靠。

只有几篇的时候，一个按时间排列的列表、一组按顺序排列的项目，已经够用。标签页和搜索可以等内容变多再做。组织方式的目的，是让下一次更新不用重新想这段话该放哪。
