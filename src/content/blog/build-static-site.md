静态站点把页面在构建时生成成 HTML。读者打开页面时，服务器只负责把文件发出去，不查数据库，也不跑业务代码。个人网站更新不频繁，这种做法足够用，也少一件要一直值守的服务。

## 为什么用 Astro

Astro 把页面和内容分开。路由放在 `src/pages`，文章放在 `src/content/blog`，共用的页头页脚放在布局组件里。文章是 Markdown，构建时变成 HTML。frontmatter 用 schema 检查：标题、摘要或日期缺了，构建会失败，而不是等有人点开才发现。

默认情况下，页面就是 HTML。没有写成交互组件的部分，不会往浏览器里塞一套框架运行时。个人站的首页、列表和正文几乎都是在展示内容，这样更合适。

## 最小目录

一条能工作的骨架可以收得很小：

```text
src/
  pages/index.astro            首页
  pages/blog/[...slug].astro   文章页
  content/blog/*.md            文章正文
  layouts/BaseLayout.astro     外壳
  styles/global.css            变量和全局样式
```

列表页从内容集合里取稿，并跳过仍标记为草稿的文件：

```ts
const posts = (await getCollection('blog', ({ data }) => !data.draft))
  .sort((a, b) => b.data.date.valueOf() - a.data.date.valueOf());
```

日期用数值比较，新文章排在前面。首页如果只展示最近几篇，排序之后再截取即可。字段名以仓库里的 `content.config.ts` 为准，不要在页面里另起一套。

## 本地先构建一次

装好依赖之后，常用的是这两条命令：

```bash
npm run dev
npm run build
```

第一条起开发服务器，改完刷新就能看。第二条生成 `dist` 目录，产物和线上一致。提交之前先构建一次。schema 不通过、frontmatter 类型不对，都会停在这一步。

## 子路径和样式

部署到子路径时要特别小心。项目站点的地址常常是域名再加上仓库名。链接如果写成以斜杠开头的绝对路径，本地从网站根打开是对的，放到子路径就会找不到页面。站内链接、图片和静态资源走统一的前缀函数，不要在每个组件里手写根路径。

样式也尽量收口。背景、正文、弱化文字、边框、强调色、圆角和字体都放进 CSS 变量。深色模式只改这些变量，卡片和文章会一起变，不用逐条选择器打补丁。

先打通一篇文章：写好 frontmatter，跑一次构建，在列表里看到标题和摘要，点进去能读到正文。导航和关于页可以随后再补。个人站容易停在半路，往往是因为栏目想得太多，结果一篇文章都没有发出去。
